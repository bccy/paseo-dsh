# 验收方案

## 子代理
- 使用独立测试父会话验证，记录原生父／子 ID 与 Paseo 子会话的对应关系。
- 子代理开始后应立即可见；子代理结束不能把仍在工作的父会话标为完成。
- 连接与每条父边都遵守真实宿主的 `session.subsession` 校验，不以绕过宿主的 fake 测试代替。
- 子代理消息、工具卡、用量不得进入父会话的同名条目，多个孩子不得互相覆盖。
- 重开父会话可恢复已持久化子代理，且不重复创建真实子代理。
- 已有用户测试会话可用于最终只读核验恢复前后的子列表；正式重载前再次确认空闲。真实新增委派只在专门的隔离验收会话运行。
- `history: skip` 只跳过父时间线回放，子目录仍需恢复；`replay` 恢复独立子历史与终态。
- 前台 spawn、fork、后台可续接路径按本机实际支持范围分别确认；外部运行时缺少本地子会话时不伪造支持。
- 本机 base 配置：`subagent` 是 `spawn + continuable`（显式 `run_in_background:false` 才前台）；`subagent_fork` 是 `fork + one-shot`。测试用确切工具和参数，不能只靠自然语言“fork模式”判断。
- 失败／取消／权限请求归属应可核对；不支持的独立操作明确返回不支持。

## 历史翻页
- 用户已确认仅 DSH 受影响，选取长 DSH 会话与短 DSH 会话作为对照。
- 分解一次上翻的时间：触发请求、服务端取得历史、返回字节数、前端插入完成。
- 比较第一次恢复和同一会话后续页，区分冷恢复与每页都慢。
- 性能改动必须提供同输入、同版本、同页大小的前后结果，不用缩减正确历史冒充提速。
- 核对消息顺序、首尾边界、工具状态、去重和滚动锚点；子代理历史与父历史分离。
- 报告本机测得的延迟与 iOS 真机尚未验证部分。
- 对照结论见 [历史对照证据](history-evidence.md)：按用户最新判据，本轮不做历史性能代码改动。

## 执行边界
- 执行者只运行不递归创建代理的隔离单元／协议测试。
- 需要真实 native 子代理的验收脚本可以由执行者准备，明确标为主会话验收入口，交主会话审核后执行。
- 不对用户正在使用的会话发送测试消息或强制取消；部署前核对运行状态。
- 主会话统一验收、重载和维护证据，独立 reviewer 只读返回结论。
- 三个真实场景在临时 profile 使用相同源码桥与已编译 provider；不同场景分开会话和数据目录，最多各委派一个直接子代理，禁止继续委派。
- 自动检查必须以实际事件建立父能力映射，不能提前把请求中的父 ID 标成已注册，也不能把 bridge 的 initialize 成功当作 Paseo 接受子会话的证据。
