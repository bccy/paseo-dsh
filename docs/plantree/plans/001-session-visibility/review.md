# 子会话映射审查

日期：2026-10-15。审查范围：基线 `1a41aba` 之后本轮子会话变更。结论：第一版不进入部署。

## 独立审查阻断
- P1：只读子 `capabilities: []` 无法承载孙级；Paseo runtime 要求每条父边的父会话具备 `session.subsession`，否则整连接失败。
- P1：连接未协商 subsession 时仍发 child opened，第一条子事件即可导致父连接失败。
- P2：现有18项 fake检查绕过宿主能力校验，未覆盖以上两项。

## 主会话验收发现
- history skip未重建子树，与恢复要求不符；子历史仅回放正文，未恢复终态，完成子卡会误显示running。
- `agent/status idle` 不是“成功”；必须结合子 `turn/end` 理由区分失败和取消。
- header先登记会丢label，重发opened不保证宿主更新；需让首次注册具有权威身份和尽量完整描述。
- 未知父、父未ready、同native子在多root视图、关闭后异步回放均需显式防护。
- 子目录查询失败不得伪报空成功，fork子回放需排除继承前缀。
- live验收仅跑bridge不能证明Paseo子注册，固定等待和父关键词检测不能作为正确性证据。
- 首版独立验收driver仍有未配置模型、根提前标已注册、恒真断言、异步close未等待等问题；浏览器脚本与“已实现点击/断言”的报告不符。已定点要求测试员修正，未用该脚本做正式验收。

## 决策
由原实现员修正源码；原测试员准备隔离真实provider验收入口；原独立reviewer在修正后定点复审。主会话仅指导、审查和执行已审核的验收入口。

## 第二版复审
- 两个P1已修复：子视图携带关系能力，root按协商门控。
- 可进入隔离真实验证，仍有P2：root已ready时孙级opened早于父级，需缓冲其事件并在父到达后释放；该项交新执行者定点修复。
- 本机宿主不消费child started/usage/permission的边界保持公开记录；不以假ID规避。

## 乱序修正复审
- P2-1已闭合：已知pending子事件/状态有界暂存，新父到达后多趟释放，未解析部分保留，防重入/去重/关闭门控通过。
- 最新源码可部署验收；37项假桥回归覆盖乱序，三条真实路径覆盖DSH bridge创建/消息/恢复。
- UI仍需正式重载后验证，不能把隔离provider通过等同于iOS真机通过。
